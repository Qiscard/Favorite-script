# PikPak 分享下载助手

ScriptCat 用户脚本：在 `mypikpak.com` 分享页扫描资源目录、获取下载直链，并按分享内的目录结构推送到 aria2 下载。媒体文件支持匿名获取；压缩包、文档等非媒体文件需要当前网页已登录。

> 脚本本体已迁入仓库 [`ScriptCat/PikPak分享下载助手.user.js`](../PikPak分享下载助手.user.js)，安装与说明见 [`MD/PikPak分享下载助手.md`](../../MD/PikPak分享下载助手.md)。本目录是开发配套：Python 参考实现、接口探测脚本与 Node 回归测试。

## 安装

1. 浏览器安装 [ScriptCat](https://scriptcat.org) 扩展
2. 直接安装 [`ScriptCat/PikPak分享下载助手.user.js`](../PikPak分享下载助手.user.js)（或 Scriptcat 面板 → 新建脚本 → 粘贴 `ScriptCat/PikPak分享下载助手.user.js` 的内容）
3. 打开任意分享页（`https://mypikpak.com/s/...`），右下角出现 **PikPak 下载助手** 按钮

## 功能

| 按钮 | 说明 |
|------|------|
| 扫描当前目录 | 列出**你当前浏览的目录**内容（见下方"目录定位"） |
| 扫描全部(递归) | BFS 遍历整个分享目录树（含子文件夹，自动翻页；中断可从断点继续） |
| ⬆上级 / 进入 | 列表中文件夹条目可直接点击"进入"扫描该目录，"⬆上级"返回上一级 |
| 恢复上次扫描 | 从本地缓存恢复最近一次扫描结果（限同一分享），刷新页面后不用重扫 |
| 全选/反选 | 勾选决定推送/导出范围，配合文件过滤与搜索框精挑要下的文件 |
| 推送 aria2 | 取直链后推送到本机 aria2 RPC，`dir`/`out` 参数按分享目录结构落盘；自动跳过 aria2 已有的同名任务 |
| 重试失败项 | 只重试上次批量推送中取链/入队失败的文件 |
| 测试连接 | 调 `aria2.getVersion` 验证 RPC 配置，失败时给出具体原因 |
| 导出列表 | 生成 aria2 输入文件（URL + dir= + out=），离线用 `aria2c -i xxx.txt` |
| 导出URL | 导出直链文本（含 `# 相对路径` 注释） |
| 中止 | 停止扫描/取链/推送（已完成部分保留） |

其他：

- **单文件下载**：列表每行"下载"按钮，≤200 MB 走内存转存（文件名保证正确），更大走 chrome.downloads 直写盘；失败会重新获取签名直链并重试一次，大文件建议推送 aria2
- **在线播放**：视频/音频行有"播放"按钮，点击后提示"正在解析"并直接流播，不经下载；原画编码（HEVC/AV1/E-AC3）浏览器放不了时可一键切换转码流
- **媒体/非媒体规则**：视频、音频、图片不设置脚本大小拦截；压缩包、文档、程序等非媒体文件需要登录，且脚本按当前分享下载策略只接受小于 100 MB
- **每日额度提示**：面板提示普通非会员每日下载额度为 20 GB，媒体文件不计入该提示；这是平台策略提示，脚本不负责强制计量，实际以账号页面为准
- **文件过滤**：按扩展名过滤导出/推送范围（如 `mkv,mp4`）
- **直链懒获取**：扫描只遍历目录；直链在推送/导出/点击时才请求（`file_info`），接近过期会刷新，失败不会永久锁死
- **取链并发**：批量取直链 3 路并发；触发 429 限流自动指数退避，恢复后间隔自动回落
- **推送去重**：推送前检查 aria2 活动/排队队列中的同名任务，避免重复推送报"文件已存在"
- **完成校验**：aria2 任务完成时核对实际大小与分享列表大小，不符时标出（可发现 CDN 错误页被存成文件）
- **断点续扫**：递归扫描中止/中断后自动保存进度，下次可从断点继续；单个目录失败重试后跳过并记录，不再整体作废
- **aria2 任务监控**：推送后保存 GID，面板轮询显示排队、下载中、速度、进度和错误；可填写和浏览器相同的 HTTP/SOCKS 代理
- **失败自动重推**：aria2 任务报错时自动重新取链并以单连接重推一次（多连接被 CDN/代理拒绝是常见失败原因）；仍失败请核对面板日志开头的配置摘要（代理/密钥/保存目录）
- **SPA 跟随**：站内切换分享时自动清空旧结果并提示重扫；面板只在分享页出现
- **提取码**：遇到加密分享，面板会显示"提取码"输入框，填写后重新扫描即可
- **配置互通**：RPC 地址/密钥/代理/保存目录/优先转码同时暴露在面板输入框和 ScriptCat 的脚本设置表单（`==UserConfig==`），两处读写同一配置
- **界面**：搜索、排序、勾选、批量进度条、单文件下载可取消、日志分级 + 清空、亮色主题跟随系统、记住面板展开状态

> 注意：大文件不要依赖扩展 Blob 转存路径。aria2 负责 Range 分段、断点续传和直接写盘；如果浏览器访问 PikPak 必须使用代理，也要在脚本的 aria2 代理框中填写同一个代理。
>
> CDN 不一定返回 `Content-Disposition`，脚本使用 `name` 参数指定文件名；签名直链本身会过期，任务失败时应重新取链。

## 目录定位（重要）

分享 URL 中 `share_id` 之后的 `AAAA...` 段是**加密的目录引用**，无法通过 API 解析（官方前端刷新后也只显示根目录）。脚本的解决办法：

- 脚本会钩住页面自身的请求；你在页面上**双击进入某个子目录**后，"扫描当前目录"就会扫描你正在看的这个目录
- 未做任何导航时，扫描从分享根目录开始（根目录通常全是文件夹，此时提示用递归扫描）

## aria2 准备

```bash
aria2c --enable-rpc --rpc-listen-all --rpc-allow-origin-all --rpc-secret=你的密钥
# 如果浏览器访问 PikPak 必须走代理，再加：
# --all-proxy=http://127.0.0.1:7890
```

脚本设置里填 RPC 地址（默认 `http://127.0.0.1:6800/jsonrpc`）、密钥、aria2 代理和保存根目录（默认 `D:/PikPak`）。先用"测试连接"按钮验证；浏览器需要代理时，aria2 也必须填写同一个代理。推送后面板会用 GID 轮询显示排队、实际速度、进度和错误。

## 播放兼容性说明

- 脚本下载默认使用 **category=original 原始直链**（原编码 mkv/mp4，已验证字节正确）
- 网页播放器报"浏览器限制无法播放"是正常的：HEVC/E-AC3/mpegts 等编码浏览器本身不支持，但**不影响下载**
- 下载的 HEVC/EAC3/AV1 文件用 VLC / PotPlayer 播放（或给系统装对应解码器）
- 若原画文件（如 AV1）本地播放器也打不开，勾选面板里的 **「优先转码」**：改取兼容性更好的转码流（通常 H.264/AAC），代价是清晰度可能更低。切换后会清空已缓存直链，下次取链按新偏好重取

## 技术原理（已验证）

媒体文件可走匿名链路；非媒体文件的 `file_info` 直链需要网页登录态：

```
POST user.mypikpak.com/v1/shield/captcha/init   ← 本地 MD5 链签名(captcha_sign) → captcha_token
GET  api-drive.mypikpak.com/drive/v1/share      ← share_id → pass_code_token + 标题
GET  /drive/v1/share/detail?parent_id=&page_token=   ← 目录遍历
GET  /drive/v1/share/file_info?file_id=          ← 媒体取 medias[].link.url；非媒体登录后取 web_content_link/octet-stream
```

- 直链为预签名 URL（`sign/expire/pr` 自包含，通常约 38 小时过期）
- 支持 HTTP Range(206)，aria2 使用 `split=8`、重试和断点续传
- 单链速度受 CDN、代理和线路影响，不在脚本内人为限速
- ScriptCat 面板中的 aria2 代理必须与浏览器访问 PikPak 使用的代理一致

## 多凭证故障转移（v0.6.0）

`captcha_sign` 的算法（clientId + clientVersion + packageName + salt 组）跟随 PikPak 客户端版本，官方一更新某套就可能失效。脚本内置 3 套凭证（`android-1.53.2` → `web-2.0.0` → `android-1.47.1`），首次打开分享时按顺序探测，哪套通就锁定并记住（`GM_setValue`），下次优先用它。单套失效仍有备份，不必手改代码。若三套全部失效（PikPak 又改了算法），需按 [crl/huangguo](https://github.com/crl/huangguo) 或 [Quan666/PikPakAPI](https://github.com/Quan666/PikPakAPI) 的最新 salt 更新 `PROFILES`。

## 已知限制

- 非媒体文件（压缩包、文档、程序等）需要登录，且当前脚本按产品策略限制为小于 100 MB；媒体文件不受此脚本大小限制
- 面板显示的普通非会员每日 20 GB 是平台规则提示，媒体文件不计入该提示；实际额度以 PikPak 账号和地区策略为准
- 超大分享（数万文件）递归扫描耗时长（API 节流 300ms/目录），建议先进到目标子目录再"扫描当前目录"
- 直链是短期签名地址，aria2 任务无速度时优先检查代理、RPC 状态和直链是否过期
- `pikpak_anon.py` 是同一逻辑的 Python 参考实现（CLI），可独立使用

## 开发

- `_test_userscript_core.js`：Node 回归测试，验证脚本内 MD5/签名算法与 crypto 一致，并覆盖文件名净化（`sanitize`）与扩展名过滤（`extAllowed`）。脚本本体在上级目录，测试通过相对路径读取，直接 `node _test_userscript_core.js` 运行即可
  （注意：本机 Node 直连 PikPak 可能被 RST——TLS 指纹过滤，属环境限制；浏览器内不受影响）
- `pikpak_share_probe.py`：单次分享目录探测脚本（CLI），用于调试接口
