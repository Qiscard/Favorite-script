# PikPak 分享下载助手使用说明

> 适用于 `ScriptCat/PikPak分享下载助手.user.js`（v0.7.0 时编写；当前版本的功能概要以 [`MD/PikPak分享下载助手.md`](../../MD/PikPak分享下载助手.md) 为准）。
>
> 本脚本运行在 PikPak 网页分享页面中，用于扫描分享目录、获取可用下载直链，并通过浏览器或 aria2 下载资源。

## 一、功能概览

脚本提供以下功能：

- 扫描当前正在浏览的分享目录
- 递归扫描分享中的全部子目录
- 保留分享目录结构推送到 aria2
- 单文件浏览器下载
- 导出 aria2 输入列表
- 导出下载直链
- 自动识别网页登录状态
- 自动处理多套 PikPak 客户端签名配置
- 监控 aria2 任务状态、速度、进度和错误
- 支持按扩展名过滤文件
- 视频原画与转码流切换
- 视频/音频在线播放（"正在解析"提示 + 内置播放器，可切转码流）
- 文件夹条目点击"进入"扫描，"⬆上级"返回
- 列表搜索、排序、勾选（全选/反选），推送/导出只处理勾选项
- 批量进度条、失败项一键重试
- 递归扫描断点续扫，单个目录失败自动跳过
- 推送前自动去重（跳过 aria2 已有的同名任务）
- 任务完成时校验文件大小是否与分享列表一致
- 提取码在面板内输入
- 恢复上次扫描结果（同一分享，刷新后免重扫）
- 单文件下载可取消
- 亮色主题跟随系统；面板展开状态自动记忆
- RPC/代理/保存目录等配置同步在 ScriptCat 脚本设置表单中编辑

## 二、安装脚本

1. 安装 [ScriptCat](https://scriptcat.org/) 浏览器扩展。
2. 打开 ScriptCat，创建一个新用户脚本。
3. 将 `ScriptCat/PikPak分享下载助手.user.js` 的全部内容复制进去并保存（或直接点击脚本文件里的安装链接）。
4. 打开 PikPak 分享页面：

   ```text
   https://mypikpak.com/s/分享ID
   ```

5. 页面右下角应出现 **PikPak 下载助手** 按钮。

脚本匹配整个 `mypikpak.com` 站点，但面板只在分享页出现：

```text
https://mypikpak.com/*
```

在站内从一个分享跳到另一个分享时（SPA 导航，页面不重载），脚本会自动清空旧分享的扫描结果并提示重新扫描。

## 三、登录状态与权限

### 3.1 媒体文件

视频、音频和图片通常可以通过分享接口获取预签名 CDN 直链。脚本对媒体文件不设置 100 MB 大小拦截，实际下载能力仍可能受到 PikPak、CDN、代理线路和分享策略影响。

常见媒体扩展名包括：

```text
mp4、mkv、avi、mov、webm、ts、m2ts、mp3、flac、wav、jpg、jpeg、png、gif、webp 等
```

### 3.2 非媒体文件

压缩包、文档、安装包和其他非媒体资源的处理规则如下：

- 必须保持 PikPak 网页已登录；
- 脚本会自动从当前页面 `localStorage` 读取登录凭证，不需要手动复制 token；
- 当前脚本限制为**小于 100 MiB** 的非媒体文件，界面显示为“小于 100 MB”；
- 达到或超过限制时，脚本会在获取直链前直接提示，不会反复请求接口；
- 非媒体文件的直链由 PikPak 登录态签发，通常不需要转存到个人网盘，因此不直接占用个人网盘空间。

### 3.3 自动读取 token

脚本会读取页面中类似下面的 localStorage 项：

```text
credentials_<client_id>
```

脚本只在内存中使用 `access_token`，不会将登录 token 写入日志、导出的 URL 文件或 `GM_setValue`。页面刷新 token 后，脚本会在后续 API 请求中重新检测。

如果 token 失效：

1. 面板登录状态会变为匿名或提示登录失效；
2. 媒体文件可以尝试退回匿名模式；
3. 非媒体文件需要重新登录 PikPak；
4. 点击 **重新检测**，或刷新 PikPak 页面后再试。

## 四、面板说明

### 4.1 登录状态栏

- 绿色圆点：已检测到有效登录态，非媒体文件可以尝试获取直链；
- 黄色圆点：匿名模式，只能使用媒体文件的匿名直链；
- **重新检测**：重新读取当前页面登录状态。

### 4.2 扫描区

#### 扫描当前目录

扫描页面当前正在显示的目录。

由于 PikPak 分享链接中第三段目录引用是内部加密引用，脚本不能仅靠 URL 解析当前目录。进入子目录时，脚本会监听页面自己的 `share/detail` 请求，以获取真实目录 ID。

建议操作顺序：

1. 在 PikPak 页面双击进入目标子目录；
2. 点击脚本的 **扫描当前目录**。

如果没有进入过子目录，脚本会从分享根目录开始扫描。

#### 扫描全部（递归）

从当前识别到的目录开始，递归扫描所有子文件夹。

分享内容很多时，递归扫描可能需要较长时间。脚本会对目录 API 请求进行节流，以降低触发风控的概率。

#### 文件过滤

可以填写扩展名过滤器，例如：

```text
mkv,mp4,avi
```

也可以填写：

```text
.zip, .rar
```

留空表示显示和处理全部文件。

#### 优先转码

默认下载原画/原始媒体流。

如果原画使用 AV1、HEVC、E-AC-3 等编码，本地播放器无法播放，可以勾选 **优先转码**。脚本会优先选择 PikPak 已生成的转码流，通常兼容性更好，但清晰度或封装格式可能有所降低。

切换该选项后，脚本会清空已缓存的媒体直链并重新获取。

## 五、单文件下载

扫描完成后，每个文件行右侧有：

- **下载**：获取直链并交给浏览器下载；
- **复制**：获取直链并复制到剪贴板。

当前 ScriptCat 版本中，单文件下载使用浏览器直连路径，以避免大文件经过扩展后台 Blob 缓冲。下载失败时脚本会：

1. 清理旧直链；
2. 重新请求 `file_info`；
3. 获取新的签名 URL；
4. 自动重试一次；
5. 仍失败时提示错误并尝试交给浏览器处理。

### 单文件下载建议

- 小文件可以直接使用列表中的 **下载**；
- **文件名规则（v0.7.1）**：≤200 MB 的文件走内存转存，文件名保证正确；更大的文件走 chrome.downloads 直写盘，若个别情况文件名不正确，请改用 aria2（`out` 参数保证命名）；
- 数百 MB、GB 级视频建议使用 aria2；
- 浏览器代理必须能访问 `dl-*.mypikpak.com` CDN；
- 直链是临时签名 URL，通常约 38 小时过期，过期后需要重新获取。

### 在线播放（不下载）

- 视频 / 音频文件行有 **播放** 按钮，点击后面板弹出约 3 秒的"正在解析"提示，解析完成后打开内置播放器直接流播（CDN 支持 Range，可拖动进度条）；
- 播放使用与下载相同的直链，不落盘、不占用下载额度路径；
- 原画编码（HEVC / AV1 / E-AC3）浏览器解码不了时，播放器内会提示并可点击 **尝试转码流重试**（兼容性更好、清晰度可能较低）；
- 按 `Esc`、点击"×"或遮罩空白处关闭播放器并停止加载。

## 六、aria2 下载

### 6.1 为什么推荐 aria2

浏览器扩展下载大文件时，可能受扩展后台、浏览器下载实现或代理线路影响。aria2 可以：

- 使用 HTTP Range 分段下载；
- 多连接下载同一个文件；
- 断点续传；
- 失败自动重试；
- 直接写入磁盘，不经过用户脚本 Blob 缓冲；
- 更适合批量和大文件下载。

### 6.2 启动 aria2 RPC

Windows 示例：

```bat
aria2c ^
  --enable-rpc ^
  --rpc-listen-all ^
  --rpc-allow-origin-all ^
  --rpc-secret=你的密钥
```

默认 RPC 地址：

```text
http://127.0.0.1:6800/jsonrpc
```

脚本面板中填写：

- **aria2 RPC**：RPC 地址；
- **RPC 密钥**：对应 `--rpc-secret`；
- **保存目录**：下载根目录，例如 `D:/PikPak`；
- **aria2 代理**：aria2 访问 PikPak/CDN 使用的代理。

先点击 **测试连接**，确认脚本能调用 `aria2.getVersion`。

### 6.3 代理配置

如果浏览器访问 PikPak 必须使用代理，aria2 通常不会自动继承浏览器代理，必须单独设置。

HTTP 代理示例：

```text
http://127.0.0.1:7890
```

SOCKS5 代理示例：

```text
socks5://127.0.0.1:7890
```

也可以在启动 aria2 时配置：

```bat
aria2c ^
  --enable-rpc ^
  --rpc-listen-all ^
  --rpc-allow-origin-all ^
  --rpc-secret=你的密钥 ^
  --all-proxy=http://127.0.0.1:7890
```

脚本面板中的代理配置会作为 `all-proxy` 传递给每个 aria2 下载任务。建议浏览器、脚本 API 和 aria2 使用同一个代理出口。

### 6.4 推送任务

1. 启动 aria2 RPC；
2. 在脚本面板填写 RPC 地址、密钥、代理和保存目录；
3. 点击 **测试连接**；
4. 扫描目录；
5. 点击 **推送 aria2**。

脚本会为每个文件设置：

```text
split=8
max-connection-per-server=8
min-split-size=4M
continue=true
max-tries=5
retry-wait=5
```

文件会根据分享中的相对路径保存。例如：

```text
分享根目录/
├── 电视剧/
│   └── 第一集.mkv
└── 电影.mp4
```

如果保存目录为：

```text
D:/PikPak
```

最终路径类似：

```text
D:/PikPak/电视剧/第一集.mkv
D:/PikPak/电影.mp4
```

### 6.5 查看实际速度

推送后不要只看“推送成功”。“推送成功”只表示 aria2 接受了任务，不代表文件已经下载完成。

面板中的 aria2 任务区会轮询显示：

- 排队中；
- 下载中；
- 完成百分比；
- 已下载大小 / 总大小；
- 当前速度；
- 当前连接数；
- 错误码和错误说明。

如果任务显示“排队中”，可能是 aria2 并发槽位不足。如果显示“下载中”但速度为 0，优先检查代理、CDN 直链是否过期以及 aria2 日志。

## 七、每日额度提示

面板会提示：

> 普通非会员每日下载额度为 20 GB，媒体文件不计入该项。

这是根据当前产品需求显示的**平台规则提示**，脚本本身：

- 不读取或修改 PikPak 账户额度；
- 不会自行统计账号每日用量；
- 不会伪造额度或绕过平台限制；
- 实际额度以 PikPak 账号、地区、会员状态和平台当前策略为准。

如果平台返回额度或权限错误，应以服务端错误为准。

### 4.3 v0.7.0 新增面板控件

- **搜索**：按路径关键字实时筛选列表；**排序**：默认顺序 / 按名称 / 按大小（大→小）；
- **全选 / 反选**：作用于当前可见条目；文件行有复选框，只有勾选的文件会被推送或导出；
- **⬆上级 / 进入**：扫描当前目录后，点文件夹条目"进入"即可列出其内容，"⬆上级"返回；
- **恢复上次扫描**：读取本地缓存的上次扫描结果（限当前分享），刷新页面后免重扫；

- **提取码**：分享需要提取码时该输入框自动出现，填写后重新扫描；
- **日志清空**：日志区右上角"清空"；错误信息以红色显示；
- **进度条**：批量取链/推送时显示整体进度。

## 八、常见问题

### 8.1 扫描结果显示 0 个视频

可能是当前目录本身只有文件夹。

处理方法：

- 进入目标子目录后点击 **扫描当前目录**；或
- 点击 **扫描全部（递归）**。

### 8.2 压缩包提示需要登录

这是预期行为。请：

1. 在同一个 PikPak 页面完成登录；
2. 点击面板中的 **重新检测**；
3. 重新扫描或重新点击文件的 **下载**。

### 8.3 非媒体文件提示超过 100 MB

当前脚本不会处理达到或超过 100 MiB 的非媒体文件。该判断在获取下载直链之前完成，因此不会因为重复请求而改变结果。

如果这是你有权限获取的大文件，可考虑：

- 使用 PikPak 官方客户端；
- 在官方支持的情况下保存到自己的网盘后下载；
- 使用其他官方提供的下载方式。

### 8.4 aria2 已入队但没有速度

按顺序检查：

1. 点击 **测试连接**，确认 RPC 可用；
2. 查看任务状态是“排队中”还是“下载中”；
3. 在 aria2 面板或日志中检查错误；
4. 确认 aria2 使用了与浏览器相同的代理；
5. 确认脚本中的 RPC 密钥正确；
6. 确认防火墙允许 aria2 访问代理和 CDN；
7. 直链过期时重新扫描或重新推送任务。

### 8.5 视频下载后无法播放

先区分“下载不完整”和“编码不兼容”：

- 检查下载文件大小是否接近分享列表中的大小；
- 使用 VLC、PotPlayer 或 ffprobe 检查文件；
- AV1、HEVC、E-AC-3 等编码可能无法被浏览器或系统默认播放器解码；
- 可以勾选 **优先转码**，重新获取兼容性更好的转码流。

### 8.6 直链复制后很快失效

PikPak 直链是带签名和过期时间的临时 CDN URL。不要长期保存直链文本；过期后重新通过脚本获取即可。

## 九、安全与隐私

- 不要把 `access_token`、`refresh_token`、captcha token 或完整签名 URL 发给他人。
- 脚本不会把登录 token 写入导出文件或日志。
- 导出的 aria2 列表包含临时下载直链，应视为敏感文件，不要公开上传。
- RPC 不建议暴露到公网；`--rpc-listen-all` 只应在可信网络中使用，并设置 RPC 密钥。
- 使用前确认自己有权访问和下载分享内容，并遵守 PikPak 服务条款及当地法律。

## 十、技术流程简述

### 媒体文件

```text
网页登录/匿名
  → captcha/init
  → share
  → share/detail
  → share/file_info
  → medias[].link.url
  → 浏览器或 aria2 下载 CDN 预签名 URL
```

### 非媒体文件

```text
网页登录
  → captcha/init + Authorization
  → share/file_info
  → web_content_link 或 application/octet-stream
  → 获取 CDN 预签名 URL
  → 浏览器或 aria2 下载
```

直链获取和文件下载是两个阶段：登录态主要用于获取非媒体文件直链；拿到 CDN 预签名 URL 后，下载阶段通常不需要再次发送 PikPak Bearer token。
